## 二、客户怎么确认

给客户确认时，不需要让客户看技术文档，只需要让客户打开线上页面逐页看。

客户每个页面只需要判断 4 件事：

1. 这个页面是否保留。
2. 页面名称、栏目顺序、按钮文字是否需要调整。
3. 当前文案大方向是否认可，中英文名称是否要换成客户内部叫法。
4. 当前图片、视频、PDF 只是占位还是已经可用，后续是否由客户通过后台替换。

如果客户暂时没有真实图片、视频、PDF、产品资料，不影响后台开发。第一期后台会先把上传入口、编辑入口、排序开关、显示开关做出来，后续由客户自己录入真实内容。

## 四、客户重点确认问题

### 4.1 页面方向

请客户确认：

1. 官网整体是否符合“高端特种纸、材料系统、外贸获客入口”的方向。
2. 是否认可当前克制、留白、材料感的视觉风格。
3. 是否需要增加更多真实工厂、纸张、样册、应用案例图片。
4. 是否有页面需要删除、合并或改名。

### 4.2 中英文文案

请客户确认：

1. 中文表达是否准确。
2. 英文表达是否符合外贸客户阅读习惯。
3. 产品名称、材料名称、工艺名称是否需要替换成客户内部标准叫法。
4. `VANGLAM`、`ArtLabel Lab`、`Artcard Lab` 等英文名称是否最终确定。

### 4.3 产品体系

请客户确认四层产品体系是否采用：

```text
Commercial Essentials / 商业基础系列
Performance Papers / 性能应用纸
Signature Materials / 高级材料体系
Bespoke & Labs / 专项定制与实验室
```

如果客户已有内部产品分类，应以客户内部分类为准。

### 4.4 选纸工具

第一版选纸工具目前是轻量规则版本。

请客户确认：

1. 应用场景是否够用。
2. 表面工艺选项是否够用。
3. 印刷/后道工艺选项是否准确。
4. 推荐结果是否需要客户提供真实纸张名称、克重、样册名称。

### 4.5 下载中心

当前下载中心只是前端展示结构。

请客户确认：

1. 哪些资料可以公开下载。
2. 哪些资料需要填写联系方式后下载。
3. 客户是否已经有 PDF、检测报告、技术表、样册文件。
4. 后台是否需要支持客户自行上传这些文件。

### 4.6 样品申请表单

请客户确认：

1. 表单字段是否足够判断客户质量。
2. 是否需要增加手机号、微信、项目预算、预计交期。
3. 表单提交后由谁接收。
4. 后续是否需要邮件通知或企业微信通知。

## 六、客户未回复时的推进原则

如果向客户确认后一直没有得到明确回复，项目不需要原地等待，可以先开发“已经确定不会浪费”的后台和 API。

可以先做的内容：

1. 后台登录、管理员账号、权限基础。
2. 媒体资源库：图片、视频、PDF、文件上传和选择。
3. 首页内容管理：首屏、按钮、导航、七大入口、新品上线视频配置。
4. 页面通用模块：标题、简介、图片、按钮、排序、显示开关。
5. 产品系列、色彩系统、表面工艺、应用场景的基础 CRUD。
6. 样册系统、下载中心、样品申请表单。
7. 官网公开 API，让官网读取后台内容。
8. 小程序字段预留，让同一套后台后续可以给小程序使用。
9. 操作日志，记录客户在后台改过什么。

暂时不需要等待客户才能做的原因：

1. 客户已经明确文字、图片、视频、资料都要由后台维护。
2. 客户已经明确后续要做小程序，并且小程序要关联同一个后台。
3. 这些功能属于后台框架和入口，不依赖客户最终素材。
4. 即使后续客户改页面名称或文案，后台字段仍然可以复用。

需要等客户确认后再定稿的内容：

1. 最终产品名称、系列名称、工艺名称。
2. 真实图片、真实视频、真实 PDF 文件。
3. 选纸工具的最终推荐规则。
4. 表单通知接收人和通知方式。
5. 是否删除某个页面或新增较大的新页面。

## 七、客户确认后的下一步

客户确认前端方向后，进入以下工作：

1. 把每个页面拆成后台字段。
2. 设计数据库表。
3. 设计后台菜单和权限。
4. 设计 API，让官网和未来小程序共用。
5. 开始后台登录、媒体资源、页面内容管理、表单管理、下载资料管理。

当前结论：

```text
客户确认前端页面方向是优先事项。
如果客户短期未回复，可以先做已知的后台、API、数据库地基。
客户最终素材和最终业务名称，等客户回复后再录入或调整。
```
