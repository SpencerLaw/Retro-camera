# 齐力纸业开发方向与需求变更记录

**创建日期**：2026 年 6 月 7 日
**用途**：记录齐力纸业项目每一次方向调整、客户新增资料、已上线状态、待开发范围和后续确认事项，避免官网、后台、小程序、服务器部署之间的信息混乱。
**适用对象**：开发方、项目负责人、客户沟通人员、后续维护人员。

## 一、为什么需要这份记录

齐力纸业项目已经出现多类资料来源：

1. 已上线的新官网前端。
2. 旧网站源码和服务器现状。
3. 已整理的后台建设需求文档。
4. 客户新发的 V1.1 PDF 交付包。
5. 后续可能继续出现的新 PDF、新截图、新口头需求。
6. 未来的小程序需求。

如果每次客户变更只靠聊天记录，很容易出现以下问题：

1. 不知道哪个需求是最新的。
2. 不知道某个功能是否已经上线。
3. 不知道某个页面属于前端、后台还是小程序。
4. 不知道某个新增需求是否包含在原预算里。
5. 不知道旧版本内容是否还要保留。
6. 不知道某个页面是否需要后台可编辑。
7. 后续开发时容易把旧文档、新 PDF、已上线代码混在一起。

因此从 2026 年 6 月 7 日开始，本项目所有重要方向调整都记录在本文件中。

## 三、当前推荐开发方向

### 3.1 新建独立项目

推荐新建独立项目：

```text
D:\webcode\qilipaper-platform
```

推荐仓库名称：

```text
qilipaper-platform
```

命名含义：

1. 不只是官网。
2. 不只是后台。
3. 不只是小程序。
4. 是官网、后台、API、数据库、资源库、小程序共用的一套业务平台。

### 3.2 推荐项目结构

```text
qilipaper-platform
├─ apps
│  ├─ web
│  │  └─ 官网前端，承载 V1.1 官网页面
│  ├─ admin
│  │  └─ 后台管理系统
│  ├─ api
│  │  └─ 统一服务端接口
│  └─ miniprogram
│     └─ 后续小程序前端，暂不立即开发
├─ packages
│  ├─ db
│  │  └─ 数据库模型、迁移、种子数据
│  ├─ shared
│  │  └─ 官网、后台、小程序共用类型
│  └─ ui
│     └─ 可复用 UI 组件，按需要建立
├─ docs
│  └─ 需求、接口、部署、变更记录
└─ README.md
```

### 3.3 推荐技术方向

结合客户新 PDF 和后续后台、小程序共用需求，推荐方向为：

```text
官网前端：Next.js App Router + TypeScript + Tailwind CSS
后台管理：Next.js / React Admin 方向
服务端 API：Node.js 服务端，统一提供官网和小程序接口
数据库：MySQL
文件资源：第一期可先放 VPS 本地，后续接阿里云 OSS
部署方式：先在客户 VPS 上部署，后续再优化自动部署流程
```

说明：

1. 客户新 PDF 明确建议 Next.js App Router。
2. 旧网站也是 Next.js，服务器已经具备 Node.js 环境。
3. 后续需要 SEO、资料中心、内容接口、小程序接口，Next.js 更适合长期维护。
4. 当前已上线的 Vite 版本可以作为视觉与内容参考，不作为最终长期架构。



## 九、固定记录规则

从今天开始，齐力纸业项目按以下规则推进。

### 9.1 客户发来新资料时

客户发来新的 PDF、截图、参考网站、文字说明、微信语音或口头需求时，先做三件事：

1. 写入本文件。
2. 写入《齐力纸业项目开发日志》。
3. 判断它属于已上线、已确认待开发、新增待确认、未来预留、明确不包含、已废弃中的哪一种。

没有写入本文件的内容，不作为正式开发依据。

### 9.2 客户确认开发范围时

客户明确说“这个要做”“这个不要做”“这个后面再说”时，需要同步更新：

1. 本文件的需求状态。
2. 后台建设需求确认清单。
3. 开发日志当天记录。
4. 如果影响报价或周期，需要单独标记。

### 9.3 开发完成某个功能时

每完成一个可展示、可测试、可上线的功能，都要记录：

1. 功能名称。
2. 完成日期。
3. 影响页面。
4. 影响后台模块。
5. 是否已经部署到服务器。
6. 是否需要客户验收。

### 9.4 上线或修改服务器时

任何服务器操作都不只写在聊天里，需要同步写入：

1. 《齐力纸业服务器操作审计记录》。
2. 《齐力纸业项目开发日志》。
3. 如影响部署结构，同时更新《齐力纸业服务器现状与新前端部署说明》。

### 9.5 每天结束前

每天结束前，至少更新一次《齐力纸业项目开发日志》，记录：

1. 今天做了什么。
2. 哪些已经完成。
3. 哪些等待客户确认。
4. 哪些影响后续开发。
5. 明天优先做什么。

## 十、当前结论

当前项目开发方向已经从：

```text
上线一个新官网前端 + 后续做基础后台
```

调整为：

```text
建设一个官网 V1.1、后台 CMS、统一 API、小程序预留的一体化内容平台
```

下一步不应直接开始写后台页面，而应先完成：

1. 独立项目建立。
2. V1.1 需求并入后台文档。
3. 第一期开发布局重新确认。
4. 最小后台到前台闭环设计。

只有这样，后续客户继续发新资料时，项目不会乱。
